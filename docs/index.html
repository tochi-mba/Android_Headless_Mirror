Built for daily use

The little details that make it feel reliable.

Lifecycle

START and STOP mean exactly what they say.

Stopping creates a persistent OFF state. Windows autostart respects it, so the mirror cannot quietly resurrect itself after you explicitly turned it off.

STOP.bat→stop.flag created→autostart blocked
START_NOW.bat→stop.flag removed→supervisor armed

Auto-open on connect

The hidden supervisor stays armed after Windows sign-in. Plug in any authorised Android phone and its mirror opens automatically, with a one-second poll interval by default.

Headless active session

Keep the physical display dark, re-send screen-off from the always-on mirror toolbar whenever needed, and keep the PC mirror active.

Wireless, when you want it

ADB-over-TCP/IP remains available as an optional fallback, but ships disabled by default.

Choose the right display path.

scrcpy remains the default capture path. Windows Wireless Display can be orchestrated separately while USB ADB stays connected for control.

Privilege is a capability, not a checkbox.

On an already-rooted device, REX can passively detect a usable route, explicitly request authorization, then expose only read-only features whose capability probes actually succeed.

Black lock screen? Still usable.

Pattern-lock phones can use runtime Android geometry first and keyboard-only calibration only when the OEM hides the real pattern view.

Display transports

Control stays on ADB. Presentation can change.

REX treats the Android control plane and the display plane separately, so normal scrcpy mirroring and an external Windows Wireless Display path can coexist with the same device connection.

01

scrcpy by default

Low-latency capture, audio, screenshots, recording, input and headless screen-off behavior stay on the proven scrcpy path.

02

Wireless Display when needed

REX probes the Windows optional feature and Miracast receive reporting, then opens the system receiver setup instead of reimplementing Wi-Fi Direct or HDCP.

03

Verify protected playback

Protected playback is never inferred from capability strings. The exact phone, PC, drivers and application must be manually tested before REX records the path as verified.

Privileged Android · Root v1

Root is a capability. Not a boolean.

Normal ADB stays the default control plane. When a device is already rooted, REX can discover that environment without prompting, request authorization only when you ask, then expose only the read-only capabilities that actually verify.

01

Passive first. rex root status checks ADB UID, boot ID, SELinux state and whether su is visible. It never invokes su.

02

Authorization is explicit. rex root request is the only Root v1 action that intentionally asks the device's superuser provider for access.

03

Verification expires with the boot. Cached trust is scoped to the Android serial + boot ID, so a reboot cannot silently inherit the previous session.

Root v1 safety boundary

There is no root installation: REX does not unlock bootloaders, patch or flash boot images, alter AVB, hide root, expose an arbitrary root shell, write partitions, or provide DRM bypass. Root access also does not make Android secure/protected video capturable.

ZERO-FRICTION ENTRY REX.bat bootstraps the app.

Release builds ship a self-contained Windows rex.exe. The bootstrap verifies the release ZIP’s SHA-256 checksum before extraction and can build locally from source when a .NET 8 SDK is available. Pattern lock guide

Discover the real Android pattern geometry first. Calibrate only when the OEM hides it.

When a secure lock screen renders black through scrcpy, the guide now asks Android for the current UI hierarchy and uses the actual pattern widget geometry whenever it is exposed.

Compatibility

Built for Android devices.
Tested on real hardware.

Android Headless Mirror is designed around standard ADB and scrcpy, not Samsung-only APIs. Core mirroring targets Windows 10/11; native Precision Touchpad pinch bridging is an enhanced Windows 11 path. Broad Android hardware compatibility is not claimed as tested.

Root compatibility is runtime-verified separately. The S21 Ultra is the project's normal ADB/scrcpy hardware baseline. REX does not claim a Magisk, KernelSU, APatch or other root-provider configuration on that phone as tested until a real rooted-device result is recorded.

Security choices are explicit

Powerful access should stay understandable.

ADB can control a lot of your phone. The project keeps the default path local and wired, and documents where convenience changes the security trade-off.

01

Wireless ADB is off by default. Enable it only when you explicitly want network reachability.

02

STOP does not kill the global ADB server. It shuts down only this package's own processes.

03

No first-unlock bypass. Android's secure boot and post-reboot PIN requirements remain intact.

04

No cloud dependency. The core mirror path is your Windows PC, ADB, scrcpy, and the connected Android device.

05

Pattern privacy stays local. Runtime UI hierarchy data is not retained; optional calibration saves only the pattern-grid rectangle, never the unlock path.

06

Root never escalates silently. Passive root status does not invoke su; authorization is explicit, boot-scoped, capability-tested and Root v1 remains read-only.

FAQ

The important questions.

Is this only for Samsung phones?

No. The project uses standard Android ADB and scrcpy. The Samsung Galaxy S21 Ultra (SM-G998B) is simply the hardware currently tested by this project.

Does REX root my phone?

No. Root v1 only uses an existing root environment. It does not unlock the bootloader, install Magisk/KernelSU/APatch, patch or flash boot images, or change verified boot. On an unrooted phone, normal ADB and scrcpy behavior stays unchanged.

Will REX ask for root access automatically?

No. rex root status and the passive probe can report that su is visible without invoking it. A superuser authorization request only happens when you explicitly run rex root request or press the corresponding Privileged action.

Does root let REX capture Netflix or other protected video?

No. Root support and protected display support are separate. REX Root v1 does not bypass DRM, Widevine, secure Android surfaces or HDCP. Protected playback still depends on a supported external-display path and the phone, receiver, drivers and application permitting it.

Can it control the phone while the physical screen is off?

Yes, scrcpy supports turning the physical display off while keeping the mirrored display active. The exact behavior can vary by Android version and manufacturer.

Can it unlock the phone for me?

It wakes the device and asks Android to dismiss the keyguard when authentication is not required. If a secure PIN/password is required, it does not bypass it. When ADB remains available, scrcpy can show the lock screen so you can authenticate from the PC. After a full reboot, some Android/OEM configurations require the first unlock on the physical device before ADB becomes available.

Does STOP really keep it stopped?

Yes. STOP creates a persistent state file and shuts down the package's mirror and supervisor. Windows autostart respects that state until you explicitly run START again.

What if my phone has no password or screen lock?

Choose “No” when the one-time prompt asks whether the device uses any screen lock. The choice is saved for that phone and no pattern-overlay process is started.

What if I use PIN, password, fingerprint or another lock instead of a pattern?

Choose that the phone has a lock, then choose “No” when asked whether it is a pattern. The device is saved as an “other” lock type and the pattern guide is not started.

Does the pattern guide know or save my unlock pattern?

No. The unlock sequence is never stored or replayed. Runtime Android UI hierarchy data is read only to locate the pattern widget. If calibration is needed, only four normalized grid bounds are saved for that device.

What if the pattern dots are not perfectly aligned on my phone?

The guide first tries exact Android pattern-cell bounds, then the runtime LockPatternView bounds. If your OEM still differs, press Ctrl+Alt+C and calibrate entirely from the PC with the arrow keys; no physical phone interaction is required.

What if automatic lock-screen detection is wrong on my phone?

With the scrcpy window focused, press Ctrl+Alt+P to manually toggle the guide. Geometry discovery and visibility detection are separate, so manual visibility still uses the best available geometry source.

What if I change my phone from pattern to PIN, or remove the lock?

Run RESET_LOCK_SCREEN_CHOICES.bat, clear that device’s saved choice, then reconnect it. The setup prompt appears again.

Can I pinch TikTok with my laptop touchpad like I would on the phone?

On Windows 11 with a Precision Touchpad, yes: pinch or spread with two fingers and the gesture is bridged into Android multitouch automatically. No modifier is required. Ctrl and Shift remain available for scrcpy's own Android gesture semantics.

How do I zoom only the PC mirror without zooming the Android app?

Hold Alt and pinch/spread on a supported touchpad, or use Alt + mouse wheel. The mirror magnification persists after Alt is released; Alt + two-finger slide pans the magnified viewport, and Reset zoom appears only when the view is above 100%.

What does the Sleep phone button do?

It re-sends scrcpy’s screen-off command to the physical Android display while the mirror stays active. Use it whenever the phone screen has been woken but you want the device dark again.

Does it require Wi-Fi?

No. USB is the default path. Wireless ADB is optional and disabled by default.

Will another Android phone work?

Yes. The supervisor targets any authorised Android device. A preferred serial only influences selection when multiple ready devices are present; it does not lock the project to the first phone you used.
